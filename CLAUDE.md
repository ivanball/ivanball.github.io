# CLAUDE.md

Personal website for Ivan Ball-llovera (`ivanball.github.io` via GitHub Pages), plus the **canonical documentation library for the whole MMCA workspace**. Plain HTML/CSS/vanilla JS with **no build step for the site pages**; the only build tooling is the docs generator under `tools/`.

**Pushing to `main` publishes the live site immediately.** This repo is not PR-gated like the four .NET repos; confirm with the user before pushing. Cross-repo workflow rules live in the workspace `../CLAUDE.md`.

## Commands

```bash
python -m http.server 8080                       # serve locally
cd tools && npm install && npm run build         # REQUIRED after ANY edit under docs-src/ or assets/data/
cd tools && npm run images                       # re-encode article heroes to WebP (incremental)
cd tools && PORT=8080 npm run resume-pdf         # re-export the resume PDF (needs a server)
cd tools && PORT=8080 npm run og-image           # re-render the social card (needs a server)
cd tools && PORT=8080 npm run a11y               # axe-core over every page type in both themes
```

The generator prints a summary (pages per collection, mermaid pages, vendored fonts, highlighted blocks, card counts, feed and sitemap sizes, pruned orphans, dead cross-links). Check it. A non-zero dead-link count usually means a wrong relative path in the markdown, not a deliberate reference to something unpublished.

CI (`ci.yml`) runs three jobs on push and PR:

1. **Freshness** rebuilds and fails if `git diff` is non-empty, converting "remember to run the build" into an enforced check. It needs a full clone, because sitemap `lastmod` comes from each file's last commit date.
2. **Links** crawls the served site with linkinator; internal links fail the build, external ones are advisory. Two traps: linkinator only recurses beneath its entry point's own path (point it at the directory root, not `index.html`), and it crawls concurrently, so a single-threaded server reports healthy files as BROKEN.
3. **Accessibility** runs `tools/a11y-check.mjs` (axe-core via puppeteer) over every page type in **both** themes, because the palette swaps entirely via `data-theme`. Deliberately not pa11y-ci: its bundled axe 4.2 cannot evaluate this stylesheet's custom properties or the `color-mix()` header background and reported contrast failures on text measuring 16.4:1.

## 1. Hand-authored pages (repo root)

`index.html`, `resume.html`, `platform.html`, `writing.html`, `speaking.html`, `contact.html`, `404.html`. There is no templating: header/footer/nav markup is **duplicated across every page** and separately inside `tools/build-docs.mjs` as `headerHtml`/`footerHtml`. A nav or footer change is one edit to `NAV_ITEMS` / `FOOTER_LINKS` in the generator plus a rebuild; every page follows.

Single edit points:
- **Writing page cards**: `assets/data/articles.js` (`window.ARTICLES` + `ARTICLE_CATEGORIES`). An empty `url` renders "Coming soon"; paste the Medium URL **and** the publication instant into `date` to publish. **The cards are static markup generated at build time**, so editing the data file is not enough: rebuild and commit the regenerated `writing.html`, `feed.xml` and `sitemap.xml` with it. `assets/js/writing.js` only filters generated nodes; it renders nothing.
- **Platform ADR card copy**: `assets/data/adr-cards.js`, keyed by ADR number. The list itself is enumerated from `docs-src/adr/`, so a new ADR appears with no edit here; an entry only replaces the generated fallback with better copy.
- **Analytics and email capture**: `assets/js/analytics.js` (GA4 id + newsletter form action). Both are placeholders and no-op until replaced. Search-console verification is a meta tag, commented in `index.html`'s head, because a crawler will not accept a JS-injected tag.
- **Published email**: `EMAIL_USER` / `EMAIL_DOMAIN` at the top of `assets/js/main.js` (assembled in JS to deter scraping; deliberately absent from the `ContactPage` JSON-LD for the same reason).
- **Figures from MMCA.Common**: `assets/data/platform-facts.js`. CI checks out this repo alone and cannot read `MMCA.Common/FACTS.md`, so they are mirrored here and stamped into the root pages; refresh them during the consumer sweep after a framework release. The ADR count is NOT here (counted from `docs-src/adr/`). The same file owns `packageLayers`, and **the build throws if its package count disagrees with `packages`**.
- **Resume**: edit `resume.html`, then re-export with `npm run resume-pdf`. Never hand-replace the PDF.
- **Social card** (`assets/img/og-image.png`): generated by `npm run og-image` **through the site's own stylesheet** off the local server, so it inherits the real tokens and fonts. Copy lives in `tools/build-og-image.mjs` and is deliberately evergreen (no counts, which would put a social card on the release treadmill). Like the resume PDF it is a **manual** step, not part of `npm run build`: a screenshot is not byte-identical across machines and font versions, and the freshness gate diffs the tree after a rebuild.
- **Article heroes**: drop the 1600x840 `article-NN.png` into `assets/img/articles/` and run `npm run images`. The PNGs are the sources uploaded to Medium; pages reference only the derived 800px `.webp`.

`assets/js/main.js` (deferred on every page) handles theme toggle (localStorage `mmca-theme`; each page also has an inline head script applying the stored theme before paint), mobile nav, footer year, doc sidebar, scroll reveal, and the on-this-page rail's active state. `assets/css/styles.css` is the single stylesheet; `assets/css/docs.css` layers doc-page prose on top.

**404.html is the one root page stamped with a root-absolute (`/`) prefix.** GitHub Pages serves it for a miss at any depth, where a relative `assets/css/styles.css` resolves under *that* directory and 404s in turn, rendering the page unstyled with dead nav links. The prefix is chosen in the root-page loop in `tools/build-docs.mjs`; the favicon tags outside the regions are root-absolute by hand.

### Site search

A native `<dialog>` stamped into the `site-header` region, so it is on every page: the nav magnifier, `Ctrl`/`Cmd`+`K`, or `/` when not typing. `<dialog>` is deliberate: focus trap, `Esc`, page inertness and backdrop come from the platform.

The index is a real inverted index, built with **MiniSearch** at build time by `tools/build-docs.mjs` into `assets/data/search-index.json`. The browser loads a finished index instead of building one, which is the only way this corpus is searchable client-side at all. Rules that break matching silently if ignored:

- **Never customize `tokenize` or `processTerm` on either side.** A function cannot cross JSON, so a custom one gives the browser a different tokenization than the index was built with. The envelope `{ v, n, o: {fields, storeFields, idField}, i }` carries the options and the runtime hands `o` straight to `MiniSearch.loadJS`; never restate them in `search.js`.
- **`normalize()` in `search.js` must match MiniSearch's default tokenizer**, so its character class splits on **dots and underscores** too: `MMCA.Common.API` becomes three ANDed words, and `"soft delete"` still finds **Soft-Delete**. Changing that class without changing the build side breaks matching quietly.
- **Ids are sequential in insertion order**, so nothing depends on hashing or iteration luck and two builds stay byte-identical for the freshness gate.
- **Indexed fields**: `t` (section title), `d` (document title), `i` (identifiers), `b` (FULL section body). `b` is indexed but **not stored**, so the whole body is searchable while only the 180-char excerpt (`x`) travels back; stored fields are `u, d, k, t, x, e`.
- **One record per H2 section**, not per page, so a hit lands on the section that answers the question. `MAX_SECTIONS_PER_DOC` caps the long tail and capped sections stay findable, because `foldSectionsIntoDocument()` folds their text and identifiers into the DOCUMENT record. Anchors come from `ctx.toc`, zipped with the source split by `splitSections()` (which skips fenced code): **do not re-slug independently**, since heading ids are deduplicated per document and would drift.
- **`toPlainText()` is indexed, `toExcerpt()` is displayed.** `toPlainText` does not truncate and **keeps table cell text**, because a comparison matrix is prose to someone hunting a term.
- **Query grammar** (`parseQuery`): bare words are **OR**; uppercase `AND` / `OR` combine explicitly with `AND` binding tighter; `"quoted"` means all those words in the same record, not a phrase (the index stores no positions). Uppercase-only operators keep a search for the word "and" working.
- **`SEARCH_OPTIONS`**: prefix matching from three characters, `fuzzy: false` (a near-miss on a type name is a wrong answer dressed as a right one), boosts `t: 3, i: 2.5, d: 2, b: 1`, and a `boostDocument` restoring the specificity BM25 lacks. Without it a long section repeating "outbox" buried ADR-003 at position 24. Highlighting uses `result.terms`, not the typed query, run on the already-escaped string so a record can never inject markup.
- Nothing ships to a visitor who never searches: `minisearch.js` is vendored by the build and injected on FIRST open, deliberately **not** in `headAssetsHtml`. URLs in the index are root-absolute so a result works from any depth. The a11y gate opens the dialog and re-runs axe, since a dialog is `display:none` until opened.

### Design system

- **Type**: Inter Variable + JetBrains Mono, both self-hosted: the build copies the woff2 files out of the `@fontsource*` devDependencies into `assets/fonts/`, so the site makes no third-party request. Latin subset only, and the `@font-face` `unicode-range` is copied verbatim from fontsource: a glyph outside it (arrows, theme-toggle symbols) falls back to the system font instead of pulling a second file. A missing package means no copy and no build failure.
- **Tokens**: a type scale (`--step--2`..`--step-4`), a spacing scale (`--space-1`..`--space-9`), and the light/dark palettes. Prefer the scale tokens over new ad-hoc rem values.
- **The ink surface** (`.ink`): every value comes from an `--ink-*` token and **those flip with the theme**. Re-pointing the base tokens locally is what lets anything nested inside stay legible with no second rule set. The band must flip: the hero is the entire viewport on load, so a band that stays dark in light mode makes the toggle look broken. Add new values as `--ink-*` tokens in both palettes; the print block neutralizes the band separately, because the print `:root` override does not reach those tokens.
- **Whole-card links**: `a.card` / `.meter-card` must stay in the `text-decoration: none` opt-out list near the top of `styles.css`, or every line of body copy inside an anchor card renders underlined.
- Any palette change has to survive `npm run a11y` in **both** themes before it lands.

`sitemap.xml` and `feed.xml` are generated, not hand-maintained. `lastmod` comes from each source file's last git commit date (uncommitted files dated today). The feed's `lastBuildDate` is the newest article's publication instant, **not** the wall clock, so consecutive builds stay byte-identical and the freshness gate is meaningful.

## 2. Generated reference library (`docs/` from `docs-src/`)

`docs-src/` holds the **canonical markdown** for the MMCA workspace documentation (centralized 2026-07-20; the .NET repos link to it, they do not own copies):

- `docs-src/adr/`: Architecture Decision Records (`NNN-*.md`); its `README.md` is the source of truth for count and range. **Add or edit ADRs ONLY here.**
- `docs-src/governance/`: the rubric plus repo-prefixed scorecards and backlogs.
- `docs-src/guides/`: public-safe narrative docs.
- `docs-src/onboarding/`: the onboarding chapters, their ONLY home; the workspace `Tools/invtool` pipeline writes here directly. Underscore-prefixed files are working files and are skipped by the build.

`tools/build-docs.mjs` renders each file into a full page in the site shell under `docs/`. **The generated HTML in `docs/` is committed: never hand-edit it.** A docs-src edit is not done until the rebuild ran and both source and regenerated output are committed together. The build also **prunes**: any `.html` under `docs/` with no surviving markdown source is deleted.

The generator writes into **marked regions of the hand-authored root pages** (`<!-- BEGIN name -->` / `<!-- END name -->`), and a missing marker fails the build rather than silently no-oping. **Never hand-edit inside a region.**

| Region | Page | Derived from |
|---|---|---|
| `head-assets`, `site-header`, `site-footer` | all 7 root pages | `NAV_ITEMS` / `FOOTER_LINKS` (also stamped into every docs page) |
| `subscribe` | `writing.html`, `platform.html` | one `subscribeHtml()`, differing only in the input id |
| `articles`, `articles-jsonld`, `article-categories` | `writing.html` | `assets/data/articles.js` |
| `featured-articles` | `index.html` | the three most recent published entries, with hero art |
| `package-layers` | `platform.html` | `packageLayers` in `assets/data/platform-facts.js` |
| `adr-list`, `adr-count` | `platform.html` | `docs-src/adr/*.md` + `assets/data/adr-cards.js` |
| `platform-stats`, `library-cards`, `scorecards` | `platform.html` | ADR count, `platform-facts.js`, the four collection sizes, and the index lines in `docs-src/governance/*-ArchitectureScorecard.md` |
| `home-stats` | `index.html` | ADR count + `platform-facts.js` |
| `resume-platform-facts` | `resume.html` | ADR count + `platform-facts.js` |

Generator behaviors worth knowing before touching it or the markdown:

- **Heading slugs are GitHub-compatible and computed from the literal heading text**, so `PagedCollectionResult<T>` slugs to `pagedcollectionresultt` and existing cross-links keep working. **Do not "fix" angle brackets in headings.**
- **Inline `<...>` that is not real HTML is escaped** via the `REAL_HTML_TAGS` whitelist, so C# pseudo-tags like `<T>` render as visible text. A doc needing a new HTML element adds it to the whitelist.
- **`.md` cross-links are rewritten to `.html`** within the library.
- **Mermaid**: ` ```mermaid ` fences become `<pre class="mermaid">` rendered client-side; `mermaid.min.js` is vendored by the build and lazy-loaded only on pages with diagrams. **Keep diagram labels free of curly braces.** Diagrams run on the `base` theme with `themeVariables` pinned to the site tokens, because the stock themes read as a foreign object dropped into the page.
- **Syntax highlighting happens at BUILD time**, so no highlighter ships to the reader; the output is `<span class="hljs-*">` coloured by `docs.css`. A fence whose language highlight.js has no grammar for (`bicep`) keeps its label and renders as plain text. Add a display name to `LANG_LABELS` when a new fence language appears.
- **On-this-page rail**: H2s become a third column on documents with at least `TOC_MIN_HEADINGS` sections, dropped first below 1180px since the sidebar already answers "where am I".

## Conventions

Never use accents, tildes, or em-dashes in prose or drafted content; use parentheses, colons, or plain characters. Avoid "seam" and "seams" (use boundary, extension point, pipeline, or layer). Applies to page copy and docs-src markdown alike. Governance commands (`/update-adrs`, `/update-scorecard`, ...) land their edits here in `docs-src/`.
