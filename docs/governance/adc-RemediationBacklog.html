    Architecture governance

    MMCA.ADC: Architecture Remediation Backlog

    Derived from ArchitectureScorecard.md (evidence as of 2026-09-22 at MMCA.Common.* v1.209.0): Maturity 97.5% (316/324) / Implementation 86.0% (697/810), weight total 81, no N/A category. Work is ranked on both scorecard axes, one band per axis. Maturity band: every category scoring maturity < 4, ranked by (4 - maturity) x weight. Implementation band: every category scoring implementation <= 8, ranked by max(0, 9 - implementation) x weight (target 9: a 10 is awardable at re-score time for an almost perfect implementation, but ranking against 10 would drown the real gaps, so 9 governs scheduling). Ties break by weight descending, then category number. Today 3 categories sit in the maturity band (8 weighted points), 14 in the implementation band (34 gap points), 31 score maturity 4 (protect, do not regress) and 19 of those also score implementation >= 9, which is the only combination that is done on both axes. This is the single remediation and tech-debt ledger: each deferred sub-item keeps its TD-NN ID with its blocker, resolution path and effort. Effort key: S = hours · M = about 1 day · L = multi-day. Right-size every fix to the measured conference load (~76 accounts / ~67 peak concurrent).

    Deliberate and accepted

    Recorded decisions, not scheduled work.

    • Single-region deployment (no multi-region failover): accepted in infra/DISASTER-RECOVERY.md, with the single SQL server and single Container Apps environment as accepted single points of failure; the measured load does not justify the cost.
    • No conference-day minReplicas:2 for the gateway/UI: the measured load does not warrant it; recorded as accepted risk in infra/DISASTER-RECOVERY.md. cost-guard.yml flags a surge that is applied and not reverted.
    • No interactive OpenAPI UI (Scalar/Swagger): the h2c-only REST services are not browser-reachable directly; a Gateway-routed UI is a small follow-up if wanted.
    • Legacy pre-cutover database retained, untouched at Basic tier, as the rollback and archive source; never written to after the per-service cutover.
    • Integration events published post-commit carrying DB-generated IDs: intentional, since the event must carry the persisted identity.
    • Constructor-dependency ceilings (§1): AuthenticationService is a cohesive auth facade and is accepted as-is. The service ceiling is 10 (:28, set for AuthenticationService), the controller ceiling 10 (Tests/Architecture/MMCA.ADC.Architecture.Tests/Cqrs/ConstructorDependencyCountTests.cs:56) and the handler ceiling 7 (:65), the last set at the widest handler (ResetPasswordHandler, SubmitQuestionHandler). SessionsController sits at 10 on a dispensation documented in the test's XML doc (ConstructorDependencyCountTests.cs:44-53): its tenth dependency, IEntityQueryService<Event, ...>, exists only for the BR-86 advisory X-Warning header on create, which the framework's fixed create-handler signature cannot set. Lower it the moment a framework change makes 9 true.
    • Vertical slice, deliberate layered-by-project hybrid (§5): cross-cutting concerns run in the decorator pipeline, slice cohesion is held by the CI-gated SliceCohesionTests, and the hybrid is the accepted choice that caps implementation at 8. It does not absorb enforcement-coverage gaps, which stay schedulable.
    • [~] Design-system residuals (§20), Common-side and watch item: eight !important overrides live in MMCA.Common's shared app.css (:189, :209-210, :297, :302, :307-308, :314, each with a mobile or a11y rationale; a generalized selector at :206); these are MMCA.Common changes, not ADC-local. ADC's own markup carries zero inline styles: layout and sizing values ride semantic classes in the module stylesheet (MMCA.ADC/Source/Modules/Conference/MMCA.ADC.Conference.UI/wwwroot/adc-ui.css:75 .text-center-cell through :308 .presenter-main, global because they land on markup MudBlazor renders), and Tests/Architecture/MMCA.ADC.Architecture.Tests/Ui/InlineStyleTests.cs:22 pins the count at zero with no allow-list (:13), so a reintroduced style=, Style= or CellStyle= fails the CI architecture tier.
    • Deploy E2E gate is chromium-only, ui-scoped and cross-engine by recency: e2e-gate invokes one browser (deploy.yml:788, browsers: '["chromium"]' at :802) and runs only on UI-affecting diffs (paired with TD-20); firefox and webkit run on alternating weekly single-engine nightly legs (Monday firefox, Thursday webkit) with continue-on-error on the schedule (e2e.yml:147). cross-browser-freshness (deploy.yml:1039, :1310, :1352) requires an in-window green proof per engine, so cross-engine coverage is enforced by recency rather than per-deploy execution: a UI deploy can ship code never run on firefox or webkit until the next weekly leg goes red and stale. backend-test-gate (deploy.yml:448-450) runs the CI.slnf unit, architecture and bUnit tier on the deploys e2e-gate skips. A deliberate Actions-minute trade-off.
    • E2E runs Blazor Server mode in CI: e2e.yml pins E2E_FORCE_SERVER=true; forcing WebAssembly in CI fails wholesale on the 2-core hosted runner (every fresh browser context pays a cold WASM boot and the readiness probe is satisfied during prerender). E2E_FORCE_WASM stays supported for local runs. Retrying WASM in CI needs all three of: a WASM-aware readiness signal, amortized per-context WASM boot, and a raised job cap. A faster self-hosted runner makes the suite fail more (Blazor Server circuits drop under sustained fast-suite load), so do not repeat the rejected test-side and circuit-config tweaks; the only paths that work are a slower pace or dedicated UI-host CPU.
    • Freshness-gate break-glass: the recency gates (dr-freshness, load-freshness, cross-service-freshness) each accept a skip_freshness_gates workflow_dispatch input with a required justification (declared at deploy.yml:13-18, per-gate checks at :562, :619, :678), so each proof is bypassable by an operator. This qualifies the "enforced deploy precondition" language used for §6, §12, §29 and §33.
    • Pseudo-localization breadth deferred (§27): broadening PseudoLocalizationTests beyond its three public pages (PseudoLocalizationTests.cs:51, public by design per :31) across the authenticated authoring surface is worth 1 weighted point and costs authenticated-login plumbing plus text-expansion and overflow assertions across roughly 54 of the 57 routable @page files, the weakest cost-to-benefit ratio on either band. The assertion is a rendered-layout property, so bUnit cannot close it, and every browser case added to the deploy-gating chromium e2e-gate is paid on every future deploy. A citable culture-aware-formatting violation also stands against the lift. §27 keeps its band row at implPriority 1, but the lever is not to be re-proposed without new evidence. Re-open triggers: a second locale beyond es, any RTL locale, or a reported layout regression on an authenticated page. Maturity 4 is unaffected (TranslationCompletenessTests + LocalizedTextConventionTests, both in MMCA.ADC.CI.slnf:58, run at deploy.yml:284).
    • BR-130 room double-booking overlap check is a SOFT guard: SessionRoomScheduling.ValidateRoomAssignmentAsync is a read-then-write advisory check with no transaction, lock or DB exclusion constraint, so two concurrent organizer writes for the same room with overlapping windows can both pass. Each alternative is rejected on evidence: a transactional re-check cannot close the race below SERIALIZABLE (which escalates to key-range or table locks across the Sessionize import path with no (RoomId, StartsAt) index); IDistributedLock's contract forbids sole-guard use on a correctness invariant and degrades to in-process when Redis is absent; sp_getapplock needs an EF/SqlClient reference the Application layer forbids. The spec's BR-130 promises only the cross-event room check (422); a double-booking is repairable by editing either session. Documented in the class XML doc (ADC PR #94). Re-open triggers: organizer concurrency materially above today's handful, a real double-booking incident, or a cheap DB-level range-exclusion capability.
    • §16 is scored, not N/A: rubric v2's "N/A in all three repos" claim (ADR-110) does not hold for ADC, because AI session scoring calls a model in production. §16 sits at M4/I10, governed by ADR-111 and ADR-120. The ADR-110 wording is a Website-side correction for /update-adrs. The two AllowAnonymous internal gRPC surfaces (Engagement.Service/Program.cs:341, Notification.Service/Program.cs:290) are accepted with their compensating controls: bounded payloads, no user ids on the wire, no Gateway route. The rubric's "no threat model" red flag stays citable (no threat-model file exists in the repo), so §11 holds at implementation 8; the mitigations such a model would enumerate are enforced individually (the CI-gated Tests/Architecture/MMCA.ADC.Architecture.Tests/Api/AnonymousEndpointTests.cs:21 allowlist, the gating supply-chain job, the compensating controls above). Re-open triggers: an explicit request for the model, a compliance requirement that names one, or a security finding a maintained model would have caught.
    • TD-15 (effort L) · topology collapse to one host and one database: the framework supports collapsing the distributed topology into a modular monolith with no application-code rewrite (AddBrokerMessaging falls back to the in-process bus, DataSourceResolver collapses the per-module sources onto one database, ModuleLoader boots all four modules in one host; MMCA.Helpdesk is the single-host proof). The recorded estimate is a run cost of ~$190-220/mo cut to roughly a third, with the gRPC partial-failure class eliminated (ACA ~$110-130, SQL ~$25, Log Analytics ~$25, Redis ~$13 at Balanced B0, Service Bus ~$10 at Standard); those dollar figures are unverified against billing. Blocker (deliberate): the distributed topology is the GTM demonstrator of the framework's extract-a-service path. Resolution path when revisited: single service host enabling all modules (Helpdesk pattern), one ADC database via the resolver collapse, drop Service Bus/Redis/Gateway from main.bicep, point the UI at the host, and re-run the k6 capacity proof at the collapsed tier.
    • Batch the feedback submit: EventFeedback/SessionFeedback send one HTTP POST per answered question over a 10-question set, each its own transaction, outbox write and audit stamp. Needs a batch upsert command and endpoint. Recorded, not scheduled.
    • Session-scoped live-poll management endpoint: SessionLive fetches event-wide polls and filters client-side. Not a type-compatible swap (GetEventPollsAsync returns LivePollDTO, the session-scoped call LivePollResultsDTO), and the event list is organizer-only with speakers falling back on 403, so it needs an authorization decision too. Recorded, not scheduled.
    • GetOpenPollsHandler issues two queries per poll: the N+1 shape SessionQuestionViewBuilder removed, one file over. Theoretical at ADC's scale (1-3 open polls), so recorded rather than fixed.
    • UI read cache not adopted (§12): the Conference UI services do not opt into IUiReadCache (zero occurrences in ADC Source); the opt-in caused e2e-gate staleness failures. This is the §12 9→10 residual.
    • [~] Optional cross-service broker-tier coverage (§14): the Testcontainers RabbitMQ + SQL round-trip tier (MMCA.ADC.CrossService.IntegrationTests, nightly cross-service-tests.yml, its recency gating deploys through cross-service-freshness) does not cover speaker analytics or the Conference→Engagement bookmark-count gRPC reads. Optional, not scheduled.
    • Dedicated rate-limit integration fixtures skipped: the WebApplicationFactory hosts neutralize the limiter; proving the 300/min cap and the per-IP registration throttle needs a tight-limit fixture variant, low value at this volume. Revisit only if abuse is observed.
    • Refresh cookie keeps SameSite=Lax, not Strict: Lax is load-bearing for the SSR-prerender path ([Authorize] pages opened in a new tab, on F5 or from an external link are cross-site top-level navigations that Strict would strip the cookie from, forcing a spurious /login bounce, the scenario ADR-022's cookie scheme exists to serve). CSRF is covered by the /auth/session/token endpoint's Sec-Fetch-Site check, POST-only, and SameSite=Lax. The session/refresh cookie lives 7 days (SessionCookieJar, aligned to the refresh-token lifetime).
    • Data export excludes feedback answers (§30): the export aggregates Identity, Engagement (bookmarks, submitted questions) and Notification (inbox items); event and session feedback answers live in the Conference database and would need a third gRPC edge. Out of scope by decision.
