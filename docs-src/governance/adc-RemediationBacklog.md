Work is ranked on both scorecard axes, one band per axis. **Maturity band:** every category scoring maturity < 4, ranked by `(4 - maturity) x weight`. **Implementation band:** every category scoring implementation <= 8, ranked by `max(0, 9 - implementation) x weight` (target 9: a 10 is awardable at re-score time for an almost perfect implementation, but ranking against 10 would drown the real gaps, so 9 governs scheduling). Ties break by weight descending, then category number. ## Deliberate and accepted

Recorded decisions, not scheduled work.

- **Closed as over-engineering.** Each was weighed against the measured load (~76 accounts, ~67 peak) and one developer; none has a defect behind it that an existing gate misses, so each would add permanent machinery for a score point. Do not re-propose without new evidence (a named re-open trigger, an incident, or an explicit ask).
  - **§22 DataGrid density toggle and organizer table reflow** (`adc-ui.css:80`, `OrganizerPointsOverview.razor:61,98`, `OrganizerAttendance.razor:57`): no user asked for density, the organizer surfaces are used on desktop, and the phone-viewport E2E (`PhoneViewportTests.cs:32`) guards the attendee pages. **Re-open:** that test fails, or an organizer reports a phone layout problem.
  - **§18 TD-16 code-behind extraction** (`SessionLive.razor.cs` at 399 of 400, `EventDetail.razor.cs` at 396): under the cap, and the cap's fitness test forces the split the day it is due.
  - **§24 `ShouldExposeFieldErrorAccessibly` on 21 more forms:** the behavior lives in the one shared `ErrorSummary`, so 21 tests would mirror one component; EventCreate pins it.
  - **§28 pixel-level visual regression:** screenshot baselines break on every MudBlazor bump and font change (the reason the Store markup-snapshot port was cut); the markup snapshots and the axe scans cover the regressions that matter.
  - **§9 baseline ratchet** keeping `openapi-baseline.json` in step with the build documents: a route added after seeding is protected once the baseline is regenerated in the pull request that changes the contract, which is the documented procedure.
  - **§5, §7, §11 and §21 (implementation) without a lever:** each would need new machinery (a slice re-layout, a broker-fed projection, a threat model, axe on every PR) against no observed defect.
  - **Batch feedback submit, session-scoped live-poll endpoint, and the `GetOpenPollsHandler` two-queries-per-poll shape:** at 1-3 open polls and a 10-question feedback form these are a handful of requests per user, and each fix needs a new command, endpoint or authorization decision.
  - **Optional cross-service broker-tier coverage** for speaker analytics and the bookmark-count gRPC read: optional by its own record, and no defect has surfaced on either path.
- **`/profile/sessions` reachable by URL, menu link Organizer-only (§25):** the framework's Signed-in devices page lists the caller's own sign-ins and revokes them per device, so it stays open to every signed-in account (`[Authorize]`, Common `Sessions.razor:1`); `Layout:SessionsNavRequiredRole` keeps its menu link to Organizers so the attendee menu holds to the conference surfaces (`MMCA.ADC.UI.Web/appsettings.json:36`, ADC commit `48691548`). Documented at `adc-NavigationFlow.md:726`.
- **Single-region deployment** (no multi-region failover): accepted in `infra/DISASTER-RECOVERY.md`, with the single SQL server and single Container Apps environment as accepted single points of failure; the measured load does not justify the cost.
- **No interactive OpenAPI UI (Scalar/Swagger):** the h2c-only REST services are not browser-reachable directly; a Gateway-routed UI is a small follow-up if wanted.
- **Integration events published post-commit carrying DB-generated IDs:** intentional, since the event must carry the persisted identity.
- **Constructor-dependency ceilings (§1):** `AuthenticationService` is a cohesive auth facade and is accepted as-is. Lower it the moment a framework change makes 9 true.
