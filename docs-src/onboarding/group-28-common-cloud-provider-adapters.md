# 28. Common Cloud Provider Adapters (AWS, Azure, GCP)

This chapter covers the three vendor adapter packages, `MMCA.Common.Aws`, `MMCA.Common.Azure` and `MMCA.Common.Gcp`. The rule they exist to keep is short: **the core packages reference no cloud SDK**. Every vendor integration lives in an adapter package that references the core, never the reverse, and a host opts in with one registration call per capability ([ADR-134](https://ivanball.github.io/docs/adr/134-cloud-neutral-core-vendor-adapters.html)). So the core defines an abstraction (or an extension point) and ships an inert default. Each adapter type implements that abstraction against one vendor SDK, and all a host has to decide is which package to reference and which calls to make. `[Rubric §3, Clean Architecture]` asks whether dependencies point inward toward policy and away from infrastructure detail. Here the vendor SDKs sit at the outermost ring, and nothing in Domain, Application or Infrastructure names them. `[Rubric §32, Dependency & Supply-Chain]` asks whether a consumer pays only for the dependencies it uses. A host that never calls an AWS adapter never restores an AWS package.

**The abstractions the adapters implement.** Five extension points in the core take an adapter. Their contracts are taught where they are declared, and this chapter only implements them:

- **File storage**: [`IFileStorageService`](group-07-persistence-ef-core.md#ifilestorageservice) (`MMCA.Common/Source/Core/MMCA.Common.Application/Interfaces/Infrastructure/Storage/IFileStorageService.cs:15`, [ADR-045](https://ivanball.github.io/docs/adr/045-managed-file-storage-and-avatars.html)). The core default is [`NullFileStorageService`](group-14-module-system-composition.md#nullfilestorageservice) (`MMCA.Common/Source/Core/MMCA.Common.Infrastructure/Storage/NullFileStorageService.cs:14`).
- **Native push**: the pair [`INativePushSender`](group-07-persistence-ef-core.md#inativepushsender) (`MMCA.Common/Source/Core/MMCA.Common.Application/Interfaces/Infrastructure/Notifications/INativePushSender.cs:12`) and [`IPushDeviceRegistrar`](group-07-persistence-ef-core.md#ipushdeviceregistrar) (`MMCA.Common/Source/Core/MMCA.Common.Application/Interfaces/Infrastructure/Notifications/IPushDeviceRegistrar.cs:11`) ([ADR-044](https://ivanball.github.io/docs/adr/044-native-push-delivery.html)). The core defaults are [`NullNativePushSender`](group-14-module-system-composition.md#nullnativepushsender) and [`NullPushDeviceRegistrar`](group-14-module-system-composition.md#nullpushdeviceregistrar) (`MMCA.Common/Source/Core/MMCA.Common.Infrastructure/Notifications/Push/NullNativePushSender.cs:12`, `NullPushDeviceRegistrar.cs:14`).
- **Broker transport**: [`IBrokerTransport`](group-14-module-system-composition.md#ibrokertransport) (`MMCA.Common/Source/Core/MMCA.Common.Infrastructure/Messaging/Transports/IBrokerTransport.cs:25`), registered through `AddBrokerTransport` (`MMCA.Common/Source/Core/MMCA.Common.Infrastructure/DependencyInjection.Messaging.cs:159`) and selected by name ([ADR-066](https://ivanball.github.io/docs/adr/066-broker-transport-selection.html), [ADR-118](https://ivanball.github.io/docs/adr/118-message-transport-library-policy.html)). The retry, redelivery and backpressure rules every transport shares live once in [`BrokerTransportPolicies`](group-14-module-system-composition.md#brokertransportpolicies).
- **PostgreSQL connection customization**: [`INpgsqlDataSourceConfigurator`](group-07-persistence-ef-core.md#inpgsqldatasourceconfigurator) (`MMCA.Common/Source/Core/MMCA.Common.Infrastructure/Persistence/DbContexts/INpgsqlDataSourceConfigurator.cs:23`), added through `AddNpgsqlDataSourceConfigurator` (`MMCA.Common/Source/Core/MMCA.Common.Infrastructure/DependencyInjection.Persistence.cs:24`).
- **Host-level ASP.NET Core extension points**: the configuration system (`IConfigurationSource`), the DataProtection key ring (`IXmlRepository`, `IXmlEncryptor`, `IXmlDecryptor`), and the OpenTelemetry pipeline that `AddServiceDefaults()` configures. These are framework types, not MMCA ones, so the adapters plug into them directly.

The rows are uneven for real reasons, not because a port is unfinished. GCP ships no broker transport. Its Cloud SQL configurator instead covers the built-in PostgreSQL broker alongside the database contexts (`MMCA.Common/Source/Hosting/MMCA.Common.Gcp/GcpServiceCollectionExtensions.cs:71-73`). Azure ships no Npgsql configurator. Its database story is Entra ID for SQL Server, which arrives through a package reference with no registration call (ADR-134, Decision). AWS ships no telemetry exporter call. The GCP notifications namespace is the largest because FCM tokens carry no owner, so the package adds its own registry and client interfaces ([`IFcmInstallationRegistry`](#ifcminstallationregistry), [`IFcmMessagingClient`](#ifcmmessagingclient)) to put Firestore and FirebaseAdmin behind something testable (`MMCA.Common/Source/Hosting/MMCA.Common.Gcp/Notifications/FirestoreInstallationRegistry.cs:16`, `FirebaseMessagingClient.cs:17`).

**How the swap works at runtime: inert core defaults, then an adapter override.** `AddInfrastructure` registers every core default with `TryAdd`: `services.TryAddTransient<INativePushSender, NullNativePushSender>()` and its registrar sibling (`MMCA.Common/Source/Core/MMCA.Common.Infrastructure/DependencyInjection.cs:353-354`), and `services.TryAddTransient<IFileStorageService, NullFileStorageService>()` (`DependencyInjection.cs:361`). The adapters register with a plain `Add`: `services.AddTransient<IFileStorageService, AzureBlobFileStorageService>()` (`MMCA.Common/Source/Hosting/MMCA.Common.Azure/AzureServiceCollectionExtensions.cs:68`), `S3FileStorageService` (`MMCA.Common/Source/Hosting/MMCA.Common.Aws/AwsServiceCollectionExtensions.cs:67`), `GcsFileStorageService` (`GcpServiceCollectionExtensions.cs:62`), and the push pairs (`AzureServiceCollectionExtensions.cs:101-102`, `GcpServiceCollectionExtensions.cs:162-163`). The adapter therefore wins whichever side runs first. Called before `AddInfrastructure`, it makes the core `TryAdd` skip. Called after, it is the last registration, which is the one a single-service resolve returns. The vendor SDK clients themselves go in with `TryAddSingleton` (for example the `BlobContainerClient` at `AzureServiceCollectionExtensions.cs:61-67`, `S3StorageClientFactory.Create` at `AwsServiceCollectionExtensions.cs:66`, and the Firestore and FCM clients at `GcpServiceCollectionExtensions.cs:159-161`). A host that registered its own client first, an emulator endpoint for example, keeps it. `[Rubric §2, Design Patterns]` asks whether patterns solve a real problem. This is the Adapter pattern with a Null Object default: application code depends on one interface, and swapping the cloud is a registration change.

**How a host selects a vendor: reference, call, then configuration as the gate.** Every adapter call is unconditional in the host and a no-op until its configuration is complete. The class summaries say so in identical words (`AzureServiceCollectionExtensions.cs:17-23`, `AwsServiceCollectionExtensions.cs:19-24`, `GcpServiceCollectionExtensions.cs:16-21`), and the bodies enforce it with early returns. Azure Blob needs a `ContainerName` plus an absolute `ServiceUri` or a `ConnectionString` (`AzureServiceCollectionExtensions.cs:49-59`). S3 needs a `Bucket` (`AwsServiceCollectionExtensions.cs:58-61`). GCS needs a `GcsBucket` (`GcpServiceCollectionExtensions.cs:56-59`). Push needs `NativePush:Enabled` plus the vendor's sub-section (`AzureServiceCollectionExtensions.cs:91-96`, `GcpServiceCollectionExtensions.cs:148-153`). The three storage adapters read the same `FileStorage` section, each through its own gate key, so a section that carries only the S3 `Bucket` or the Azure `ContainerName` leaves the GCS call inert (`GcpServiceCollectionExtensions.cs:32-40`). The builder-level calls follow the same posture with a single gate key each: `KeyVault:Uri` (`AzureKeyVaultConfigurationExtensions.cs:80`), `SecretsManager:NamePrefix` (`AwsSecretsManagerConfigurationExtensions.cs:82`), `DataProtection:BlobStorageUri`, `SsmParameterPrefix` or `GcsObjectUri` (`AzureDataProtectionExtensions.cs:53`, `AwsDataProtectionExtensions.cs:57`, `GoogleCloudDataProtectionExtensions.cs:76`), `APPLICATIONINSIGHTS_CONNECTION_STRING` (`AzureMonitorExporterExtensions.cs:42`) and `GoogleCloudTelemetry:ProjectId` (`GoogleCloudTelemetryExporterExtensions.cs:101`). The result is that local development and tests take no cloud dependency at startup, and a deployment switches a capability on through configuration alone. The secrets sources are deliberately not called from `AddServiceDefaults()` for exactly that reason. They also use one naming convention (a double dash maps to the configuration separator, so `ConnectionStrings--Default` arrives as `ConnectionStrings:Default`), which lets a secret set move between Key Vault and Secrets Manager by renaming its prefix alone. Both points are recorded on `AzureKeyVaultConfigurationExtensions.cs:80` and `AwsSecretsManagerConfigurationExtensions.cs:82`.

**Broker transports are selected by name, not by type.** `AddBrokerMessaging` picks the bus from the string `MessageBus:Provider`. `RabbitMq`, `PostgreSql` and `InProcess` are built in, and any other name must match an [`IBrokerTransport`](group-14-module-system-composition.md#ibrokertransport) an adapter registered earlier. A name with no registered transport throws, naming the package and the call (`MMCA.Common/Source/Core/MMCA.Common.Infrastructure/DependencyInjection.Messaging.cs:24-36`). The two adapter calls are therefore one-liners that hand a transport instance to `AddBrokerTransport`: `AddAzureServiceBusTransport()` (`AzureServiceCollectionExtensions.cs:117-118`) and `AddAmazonSqsTransport()` (`AwsServiceCollectionExtensions.cs:85-86`). Each transport reports its provider name through `Name` (`MMCA.Common/Source/Hosting/MMCA.Common.Azure/Messaging/AzureServiceBusTransport.cs:22`, `MMCA.Common/Source/Hosting/MMCA.Common.Aws/Messaging/AmazonSqsTransport.cs:69`). The ordering is load-bearing: the adapter call must come BEFORE `AddBrokerMessaging`, which picks the transport while it registers the bus (`AzureServiceCollectionExtensions.cs:108-110`, `AwsServiceCollectionExtensions.cs:73-75`). Vendor limits surface at registration. The SQS transport defaults an unconfigured `MessageBus:RedeliveryIntervalsSeconds` to `[60, 300, 900]`, and a configured value over 900 (the SQS delay cap) makes `AddBrokerMessaging` throw (`AwsServiceCollectionExtensions.cs:78-81`). A Service Bus connection string carrying `UseDevelopmentEmulator=true` targets the local emulator through [`ServiceBusEmulatorSupport`](#servicebusemulatorsupport) and needs `MessageBus:EmulatorAdminEndpoint` (`AzureServiceCollectionExtensions.cs:111-113`). `[Rubric §10, Messaging & Integration]` asks whether transport choice is isolated from message semantics. Here the semantics live in the core and its shared policies, and the adapter supplies only the wire.

**Identity instead of stored credentials.** Each adapter defaults to the platform's ambient identity and treats a static key as the exception. Azure uses `DefaultAzureCredential` for Blob, Key Vault and the DataProtection blob (`AzureServiceCollectionExtensions.cs:64`, `AzureKeyVaultConfigurationExtensions.cs:80`, `AzureDataProtectionExtensions.cs:53`). GCP uses Application Default Credentials and has no key-file or HMAC setting at all (`GcpServiceCollectionExtensions.cs:37-38`, `:123-125`). AWS falls back to the default credential chain unless `AccessKeyId` and `SecretAccessKey` are both set. [`AwsStaticCredentials`](#awsstaticcredentials) enforces the both-or-neither rule at registration rather than on the first call (`AwsServiceCollectionExtensions.cs:63-64`, `:117-120`). The two PostgreSQL configurators push the same idea down to the database connection. [`RdsIamAuthenticationConfigurator`](#rdsiamauthenticationconfigurator) and [`CloudSqlIamAuthenticationConfigurator`](#cloudsqliamauthenticationconfigurator) both implement [`INpgsqlDataSourceConfigurator`](group-07-persistence-ef-core.md#inpgsqldatasourceconfigurator) (`MMCA.Common/Source/Hosting/MMCA.Common.Aws/Rds/RdsIamAuthenticationConfigurator.cs:20-21`, `MMCA.Common/Source/Hosting/MMCA.Common.Gcp/CloudSql/CloudSqlIamAuthenticationConfigurator.cs:23`). Each replaces the password with a short-lived token: an RDS token refreshed every 10 minutes, or a Cloud SQL OAuth2 token refreshed every minute, retried 30 seconds after a failure in both cases (`AwsServiceCollectionExtensions.cs:89-92`, `GcpServiceCollectionExtensions.cs:68-72`). Because that token travels as the password, both registration calls refuse any configured PostgreSQL connection string that does not require TLS, and they refuse it at startup, not on the first query (`AwsServiceCollectionExtensions.cs:122-124`, `GcpServiceCollectionExtensions.cs:100-102`). `[Rubric §11, Security]` asks whether secrets are kept out of code and configuration and whether credentials are short-lived. These adapters are where the framework answers that question for each cloud.

**Scale-out and observability concerns at the host level.** The three DataProtection calls fix one specific multi-replica failure. The framework default keeps the key ring in memory, so a cookie or antiforgery token minted by one replica cannot be decrypted by another. Persisting the ring to one shared store (an Azure blob, SSM Parameter Store, or one Cloud Storage object) gives every replica the same keys (the class summaries above `AzureDataProtectionExtensions.cs:20`, `AwsDataProtectionExtensions.cs:21` and `GoogleCloudDataProtectionExtensions.cs:22`). GCP is the one vendor that builds its own repository and KMS encryptor and decryptor: [`GcsXmlRepository`](#gcsxmlrepository) implements `IXmlRepository`, and [`GcpKmsXmlEncryptor`](#gcpkmsxmlencryptor) and [`GcpKmsXmlDecryptor`](#gcpkmsxmldecryptor) implement the framework's XML encryption interfaces (`MMCA.Common/Source/Hosting/MMCA.Common.Gcp/DataProtection/GcsXmlRepository.cs:31`, `GcpKmsXmlEncryptor.cs:25`, `GcpKmsXmlDecryptor.cs:16`). It rewrites the single object under a generation precondition so two replicas cannot overwrite each other's new key (documented on `GoogleCloudDataProtectionExtensions.cs:76`). The two telemetry calls add a vendor exporter beside the vendor-neutral OTLP exporter that `AddServiceDefaults()` configures, and both must run AFTER it so the service-defaults filter processors see spans first. Both enforce that order even when their gate key is unset, so a misordered host fails on a developer machine (`AzureMonitorExporterExtensions.cs:42`, `GoogleCloudTelemetryExporterExtensions.cs:101`). The Google exporter sends traces and logs only. Metrics go through a collector because the Telemetry API caps a metric request at 200 data points (recorded on `GoogleCloudTelemetryExporterExtensions.cs:101`). Its token is fetched by the hosted service [`GoogleCloudTelemetryAccessToken`](#googlecloudtelemetryaccesstoken) at host start, never at registration (`MMCA.Common/Source/Hosting/MMCA.Common.Gcp/Telemetry/GoogleCloudTelemetryAccessToken.cs:28-30`). `[Rubric §13, Observability & Operability]` asks whether telemetry reaches an operator without coupling code to a backend. Here the instrumentation stays vendor-neutral and only the exporter is chosen per cloud.

**Guardrails against a silently missing adapter.** A quiet default is right for a host that never switched a capability on and wrong for one that did. The core closes that gap with the internal `CloudAdapterTripwire` options validator, wired with `ValidateOnStart` in `AddInfrastructure` (`DependencyInjection.cs:217-223`, class at `MMCA.Common/Source/Core/MMCA.Common.Infrastructure/Configuration/CloudAdapterTripwire.cs:30`). When `NativePush:Enabled` is true but the resolved `INativePushSender` is still `NullNativePushSender`, the host fails startup with a message naming the adapter call to add (`CloudAdapterTripwire.cs:48-53`). File storage is deliberately unchecked. A `FileStorage` section is routinely shared across every service of a solution, so it does not declare intent, and a host that does store files without an adapter is not silent anyway, because `NullFileStorageService` fails every upload with `FileStorage.NotConfigured` (`CloudAdapterTripwire.cs:22-27`). The dependency direction itself is a fitness test. [`CloudVendorIsolationTestsBase`](group-29-testing-infrastructure.md#per-project-test-rollup) asserts that the core references no vendor SDK, beside a compile-time `EnforceCloudVendorBoundary` guard (ADR-134, Decision; restated in `MMCA.Common/AGENTS.md`, "Cloud vendor adapters"). `[Rubric §34, Architecture Governance & Documentation]` asks whether a decision is enforced rather than only written down, and this one is enforced twice.

**Where it is used.** MMCA.ADC is the Azure adopter, and every call it makes comes from `MMCA.Common.Azure`. Each service host calls `AddAzureKeyVaultConfiguration()` and `AddAzureMonitorExporter()` (for example `MMCA.ADC/Source/Services/MMCA.ADC.Conference.Service/Program.cs:115,122`). The broker services call `AddAzureServiceBusTransport()` (`MMCA.ADC/Source/Services/MMCA.ADC.Conference.Service/Program.cs:428`, `MMCA.ADC/Source/Services/MMCA.ADC.Identity.Service/Program.cs:339`). Conference and Identity call `AddAzureBlobFileStorage` (`MMCA.ADC/Source/Services/MMCA.ADC.Conference.Service/Program.cs:367`, `MMCA.ADC/Source/Services/MMCA.ADC.Identity.Service/Program.cs:261`). The Notification module calls `AddAzureNotificationHubsPush` (`MMCA.ADC/Source/Modules/Notification/MMCA.ADC.Notification.API/DependencyInjection.cs:40`). Identity and the Blazor web host call `AddAzureDataProtection()` (`MMCA.ADC/Source/Services/MMCA.ADC.Identity.Service/Program.cs:127`, `MMCA.ADC/Source/Hosts/UI/MMCA.ADC.UI.Web/Program.cs:72`). No host under `MMCA.ADC/Source` calls an AWS or GCP adapter. Those two packages are exercised by Common's own LocalStack and emulator test tiers, not by an MMCA.ADC deployment. The registration calls are C# `extension(T)` members, read as described in the [primer](00-primer.md#c-extensiont-types--read-this-once).

### AmazonSqsTransportSettings
> MMCA.Common.Aws · `MMCA.Common.Aws.Messaging` · `MMCA.Common/Source/Hosting/MMCA.Common.Aws/Messaging/AmazonSqsTransportSettings.cs:8` · Level 0 · class

- **What it is**: the bound options class for the Amazon SQS/SNS broker transport, read from the `MessageBus:AmazonSqs` section (`AmazonSqsTransportSettings.cs:11`).
- **Depends on**: nothing first-party; `System.Uri` for the endpoint override.
- **Concept**: a vendor-specific sub-section of the provider-neutral [`MessageBusSettings`](group-14-module-system-composition.md#messagebussettings). The neutral settings carry the redelivery policy; this class carries only what SQS addressing needs. `[Rubric §10, Messaging & Integration]` assesses whether broker choice is a configuration concern rather than a code change; here the SQS addressing lives in its own section so the shared `MessageBus` keys stay transport-agnostic.
- **Walkthrough**: four `init` properties. `Region` (`AmazonSqsTransportSettings.cs:18`) is a region system name; blank defers to the AWS SDK fallback chain, and no region at all fails registration (enforced by [`AmazonSqsTransport`](#amazonsqstransport)). `ServiceUrl` (`AmazonSqsTransportSettings.cs:24`) is one endpoint override for both SQS and SNS, honored only when absolute. `AccessKeyId` / `SecretAccessKey` (`AmazonSqsTransportSettings.cs:31,34`) are an optional static key pair, both-or-neither (enforced by [`AwsStaticCredentials`](#awsstaticcredentials)).
- **Why it's built this way**: every field is optional because the AWS default chains (region and credentials) are the production path for an IAM-role host; the static pair and endpoint override exist for LocalStack and non-AWS environments. Transport selection by configuration is recorded in [ADR-066](https://ivanball.github.io/docs/adr/066-broker-transport-selection.html), the fail-at-registration posture in [ADR-070](https://ivanball.github.io/docs/adr/070-fail-fast-configuration-contract.html).
- **Where it's used**: read once inside [`AmazonSqsTransport`](#amazonsqstransport)`.Configure` (`MMCA.Common/Source/Hosting/MMCA.Common.Aws/Messaging/AmazonSqsTransport.cs:78-79`) and named in its error messages (`AmazonSqsTransport.cs:87,183`).

### AwsClientEndpoint
> MMCA.Common.Aws · `MMCA.Common.Aws` · `MMCA.Common/Source/Hosting/MMCA.Common.Aws/AwsClientEndpoint.cs:11` · Level 0 · class (internal static)

- **What it is**: a one-method helper that points any AWS SDK `ClientConfig` at either a custom endpoint or an AWS region, from the `ServiceUrl` / `Region` pair every AWS settings section in this package carries.
- **Depends on**: nothing first-party; AWS SDK `ClientConfig` and `RegionEndpoint`.
- **Concept**: one shared rule for endpoint resolution, so SNS, DynamoDB, S3 and Secrets Manager clients interpret the same two keys identically. `[Rubric §15, Best Practices & Code Quality]` assesses whether duplicated logic is factored once; this helper is that single copy.
- **Walkthrough**: `Apply(config, serviceUrl, region)` (`AwsClientEndpoint.cs:23`). An absolute `serviceUrl` wins: it sets `config.ServiceURL` (`AwsClientEndpoint.cs:29`) and, when a region is also given, uses it as the signing region via `AuthenticationRegion` (`AwsClientEndpoint.cs:32`). Otherwise a non-blank region sets `RegionEndpoint` (`AwsClientEndpoint.cs:37`). Neither set leaves the client on the SDK region fallback chain.
- **Why it's built this way**: the doc comment records that the SDK treats the two as mutually exclusive (setting a region endpoint clears the service URL, `AwsClientEndpoint.cs:16-17`), hence the explicit branch rather than setting both. The endpoint override is what lets LocalStack, MinIO and Cloudflare R2 stand in for AWS (`AwsClientEndpoint.cs:13-15`).
- **Where it's used**: [`SnsPushClientFactory`](#snspushclientfactory) (`MMCA.Common/Source/Hosting/MMCA.Common.Aws/Notifications/SnsPushClientFactory.cs:23,39`), [`S3StorageClientFactory`](#s3storageclientfactory), and [`AwsSecretsManagerConfigurationExtensions`](#awssecretsmanagerconfigurationextensions) (`MMCA.Common/Source/Hosting/MMCA.Common.Aws/AwsSecretsManagerConfigurationExtensions.cs:118`). [`AmazonSqsTransport`](#amazonsqstransport) does not use it: MassTransit's host configurator takes the region and endpoint separately (`AmazonSqsTransport.cs:92,102-103`).

### AwsStaticCredentials
> MMCA.Common.Aws · `MMCA.Common.Aws` · `MMCA.Common/Source/Hosting/MMCA.Common.Aws/AwsStaticCredentials.cs:9` · Level 0 · class (internal static)

- **What it is**: the shared both-or-neither rule for an `AccessKeyId` / `SecretAccessKey` pair.
- **Depends on**: nothing first-party; AWS SDK `BasicAWSCredentials`.
- **Concept**: a half-configured credential is a configuration error, not a fallback. `[Rubric §11, Security]` assesses whether identity is explicit and least-surprise; the doc comment states the reason directly: silently falling back to the default chain "would run the host under an identity nobody configured" (`AwsStaticCredentials.cs:14-15`).
- **Walkthrough**: `Resolve(accessKeyId, secretAccessKey, sectionPath)` (`AwsStaticCredentials.cs:22`) returns a `BasicAWSCredentials` when both halves are set (`AwsStaticCredentials.cs:27-29`), throws `InvalidOperationException` naming both keys under `sectionPath` when exactly one is set (`AwsStaticCredentials.cs:32-35`), and returns `null` when both are blank (`AwsStaticCredentials.cs:38`), which callers read as "use the AWS default credential chain".
- **Why it's built this way**: the check runs at registration time in every caller, matching [ADR-070](https://ivanball.github.io/docs/adr/070-fail-fast-configuration-contract.html): a misconfiguration surfaces at startup rather than on the first upload, send or query.
- **Where it's used**: [`AwsServiceCollectionExtensions`](#awsservicecollectionextensions) (`MMCA.Common/Source/Hosting/MMCA.Common.Aws/AwsServiceCollectionExtensions.cs:64,117,178`), [`AwsSecretsManagerConfigurationExtensions`](#awssecretsmanagerconfigurationextensions) (`AwsSecretsManagerConfigurationExtensions.cs:97`), [`AmazonSqsTransport`](#amazonsqstransport) (`AmazonSqsTransport.cs:86`) and [`S3StorageClientFactory`](#s3storageclientfactory).

### RdsIamAuthenticationSettings
> MMCA.Common.Aws · `MMCA.Common.Aws.Rds` · `MMCA.Common/Source/Hosting/MMCA.Common.Aws/Rds/RdsIamAuthenticationSettings.cs:8` · Level 0 · class (internal sealed)
